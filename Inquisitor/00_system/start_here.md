- `editor_protocol.md` — когда дойдёт до редактуры главы.
- Файлы `mir/` — когда нужна справка по миру (религия, законы, языки).

- Файлы `20_plots/case_NNN/*` — когда работаем над делом.

### Первое сообщение в чат

**Шаблон:**

```
// режим режиссёра //

День 1. 15 мая 1590. [локация]. Начинаю.

[Далее — либо зацепка для дела, либо команда.]
```

**Примеры первых сообщений:**

**Вариант A — с зацепкой:**
```
// режим режиссёра //

Зацепка: донос от жреца храма Каменщиков. Тема — тайное собрание в доме нотариуса.
```

**Вариант B — без зацепки, «брось преступление»:**
```
// режим режиссёра //

День 1. 15 мая 1590. Трикастелла, трибунал. Начинаю.

Трибунал, брось преступление.
```

**Вариант C — с явной локацией:**
```
// режим режиссёра //

День 1. 15 мая 1590. Трикастелла, покои Инквизитора, утро. Начинаю.

Жду утренний доклад секретаря.
```

## §2. КОМАНДЫ УПРАВЛЕНИЯ

Все команды начинаются со слова **`Трибунал`**. Пишутся **в любом месте сообщения** — можно в начале, середине, конце.

### §2.1. Как выделять команды

**Правило:** команды **не требуют** специальных скобок, кавычек или слэшей. Но **для ясности** можно выделять:

- **Рекомендуется:** `Трибунал, итог` — как есть.
- **Допустимо:** `[Трибунал, итог]` — в квадратных скобках, если в сообщении много текста.
- **Допустимо:** `Трибунал, итог.` — с точкой, если в конце предложения.
- **Не нужно:** `/Трибунал, итог` или `//Трибунал, итог//` — слэши зарезервированы под **триггеры режима** (`// режим режиссёра //`).

**Триггеры режима** (всегда с двойными слэшами):
- `// режим режиссёра //`
- `// режим протагониста //`

**Другие триггеры** (тоже с двойными слэшами):
- `// противодействие //`
- `// не веди сюжет //`
- `// изоляция //`
- `// новые арки //`
- `// без патетики //`
- `// физиология //`
- `// разговор //`
- `// живо //`

### §2.2. Список команд — по назначению

#### A. После сцены (рутина)

**1. `Трибунал, итог`**
- **Когда:** сразу после сцены.
- **Что делает:** применяет дельту (merge; без песочницы — выводит полный state для замены), выдаёт строку времени, доску нитей.
- **Частота:** **1 раз после сцены.** Не чаще.
- **Пример:** `Трибунал, итог.`

**2. `Трибунал, итог дня`**
- **Когда:** при смене дня (переход через ночь, сон, скачок времени).
- **Что делает:** `day_close` — summary дня (2–3 предложения), закрытие дневной хроники, старт новой.
- **Частота:** **1 раз в день** (по сюжету).
- **Пример:** `Трибунал, итог дня.`

#### B. Состояние (по необходимости)

**3. `Трибунал, дамп`**
- **Когда:** нужно **полностью** выгрузить state.
- **Что делает:** выводит полный `inquisitor_state.md` — замена файла.
- **Частота:** **редко.**
- **Пример:** `Трибунал, дамп.`

**4. `Трибунал, merge`**
- **Когда:** если дельта не применилась автоматически.
- **Что делает:** применяет дельту к state (Code Interpreter или полный вывод для замены).
- **Частота:** по необходимости.
- **Пример:** `Трибунал, merge.`

**5. `Трибунал, срез [имена]`**
- **Когда:** нужна **сводка** по конкретным NPC.
- **Что делает:** ручной инжектор — карточки участников + knows + хроника за 2 дня + видимые улики.
- **Частота:** **редко** (обычно автоматически).
- **Пример:** `Трибунал, срез Инквизитор, секретарь, судья.`

#### C. Хроника (раз в ~10 итераций)

**6. `Трибунал, протокол`**
- **Когда:** раз в ~10 итераций или по важному событию.
- **Что делает:** полная хроника + карточки всех NPC.
- **Частота:** **раз в ~10 сцен.**
- **Пример:** `Трибунал, протокол.`

**7. `Трибунал, аудит`**
- **Когда:** раз в ~10 итераций, **вместе с `протоколом`**.
- **Что делает:** проверка соответствия `mir/` + `lore_local.md`. См. `editor_protocol.md` §1.
- **Частота:** **раз в ~10 сцен.**
- **Пример:** `Трибунал, аудит.`

#### D. Закрепление (точечно)

**8. `Трибунал, закрепить [название]`**
- **Когда:** важное событие — надо зафиксировать.
- **Что делает:** `pinned: true` в `key_events`.
- **Частота:** по необходимости.
- **Пример:** `Трибунал, закрепить Дело о нотариусе.`

**9. `Трибунал, открепить [название]`**
- **Когда:** событие потеряло актуальность.
- **Что делает:** `pinned: false`.
- **Частота:** по необходимости.
- **Пример:** `Трибунал, открепить Дело о нотариусе.`

#### E. Редактура (после главы)

**10. `Трибунал, редактор [текст]`**
- **Когда:** глава готова, нужна редакторская вычитка.
- **Что делает:** принудительный `[EDITOR]` — 4 прохода по `editor_protocol.md`.
- **Частота:** после каждой главы.
- **Пример:** `Трибунал, редактор [текст главы].`

#### F. Броски (смешанный режим)

**11. `Трибунал, брось преступление`**
- **Когда:** нужно **новое дело**.
- **Что делает:** бросок d20 по таблице преступлений.
- **Частота:** при старте нового дела.
- **Пример:** `Трибунал, брось преступление.`

**12. `Трибунал, брось улику`**
- **Когда:** нужна улика в расследовании.
- **Что делает:** бросок d20 по таблице улик.
- **Частота:** когда сюжет провисает.
- **Пример:** `Трибунал, брось улику.`

**13. `Трибунал, брось поворот`**
- **Когда:** нужен поворот в расследовании.
- **Что делает:** бросок d12 по таблице поворотов.
- **Частота:** когда сюжет провисает.
- **Пример:** `Трибунал, брось поворот.`

**Правило:** система **может** бросить сама, если нужно. Автор **может** запросить. Автор **может** выбрать результат **вручную** из таблицы.

### §2.3. Список команд — по последовательности

**Обычная сцена:**

1. Сцена идёт.
2. `Трибунал, итог` — после сцены.

**Конец дня:**

1. `Трибунал, итог` — после последней сцены дня.
2. `Трибунал, итог дня` — закрытие дня.

**Раз в ~10 сцен:**

1. `Трибунал, протокол`.
2. `Трибунал, аудит`.

**Закрепление важного:**

1. `Трибунал, закрепить [название]`.

**Работа над делом (большой цикл):**

1. Автор даёт зацепку.
2. Система задаёт 5–7 уточняющих вопросов.
3. `Трибунал, брось преступление` — если нужно.
4. Фабула собирается.
5. Автор правит.
6. Сюжет собирается.
7. Автор правит.
8. Главы собираются.
9. Фиксация.

**Работа над главой (малый цикл):**

1. Фабула главы.
2. Автор правит.
3. Сюжет главы.
4. Автор правит.
5. Проза (в режиме РЕЖИССЁРА по умолчанию).
6. Автор правит.
7. `Трибунал, редактор [текст главы]` — 4 прохода.
8. Готовый текст → `30_manuscript/book_01/ch_NNN.md`.

## §3. ЧЕГО НЕ ДЕЛАТЬ

- **Не писать `/Трибунал`** — слэш зарезервирован под триггеры режима.
- **Не писать `//Трибунал//`** — двойные слэши только для триггеров режима и настроек.
- **Не писать команды слитно** — `Трибуналитог` не распознается. Нужна **запятая**: `Трибунал, итог`.
- **Не сокращать ссылки** — только полные raw-URL.
- **Не использовать кириллицу в именах файлов** — только ASCII.
- **Не присылать «прочитай `Inquisitor/chat_s_ii`»** — это не команда чтения. Для чтения — **полная ссылка** или **вложение**.
