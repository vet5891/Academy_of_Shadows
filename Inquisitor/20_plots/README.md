# 20_plots — структура дел

> Здесь хранятся **большие циклы** (дела) и **малые циклы** (главы).
> Система читает файлы по мере работы. Автор редактирует вручную.
> Формат: markdown. ASCII-имена папок и файлов.

---

## Структура

```
20_plots/
├── README.md                    (этот файл)
├── case_001/
│   ├── 00_fabula.md             фабула большого события (1 стр.)
│   ├── 01_synopsis.md           сюжет (3–5 актов)
│   ├── 02_chapters.md           деление на главы (50–250)
│   └── chapters/
│       ├── ch_001/
│       │   ├── fabula.md        фабула главы (1 абзац)
│       │   ├── synopsis.md      сюжет главы (3–5 сцен)
│       │   └── draft.md         проза (черновик)
│       ├── ch_002/
│       │   └── …
│       └── …
├── case_002/
│   └── …
└── …
```

## Правила

1. **Номер дела** — `case_NNN` (трёхзначный).
2. **Номер главы** — `ch_NNN` (трёхзначный, для сортировки).
3. **Файлы** — с префиксами (`00_`, `01_`, `02_`) для порядка.
4. **Готовый текст** — переносится в `30_manuscript/` после редакторской вычитки.
5. **Промежуточные версии** — остаются в `chapters/ch_NNN/`, не удаляются.

## Как работает

**Большой цикл:**
1. Автор даёт зацепку.
2. Система задаёт 5–7 уточняющих вопросов.
3. Система собирает `00_fabula.md`.
4. Автор правит.
5. Система собирает `01_synopsis.md`.
6. Автор правит.
7. Система собирает `02_chapters.md`.
8. Автор правит.
9. Дело зафиксировано.

**Малый цикл (на каждую главу):**
1. Система пишет `ch_NNN/fabula.md`.
2. Автор правит.
3. Система пишет `ch_NNN/synopsis.md`.
4. Автор правит.
5. Система пишет `ch_NNN/draft.md` (в режиме РЕЖИССЁРА по умолчанию).
6. Автор правит.
7. Редакторская вычитка через `editor_protocol.md`.
8. Готовый текст → `30_manuscript/book_01/ch_NNN.md`.
